# Requirements Archive: v0.3 Magic String Elimination

**Milestone:** v0.3 — Magic String Elimination
**Shipped:** 2026-08-11
**Requirements:** 19 (MAINT-01 through MAINT-19)
**Status:** ✅ All requirements validated

## Requirements

### Core Protocol Constants

- [x] **MAINT-01**: URL path constants (`/app`, `/app?hl={}`, `/_/BardChatUi/data/batchexecute`, `/usage`, `/scheduled`, `/app/{id}`) are centralized and referenced by name instead of inline strings.
- [x] **MAINT-02**: batchexecute query parameter keys (`rpcids`, `source-path`, `hl`, `_reqid`, `rt`, `bl`, `f.sid`) are centralized as named constants.
- [x] **MAINT-03**: batchexecute transport strings (`wrb.fr`, XSSI prefix, `f.req`, `batchexecute` endpoint discriminator) are centralized as named constants.
- [x] **MAINT-04**: WIZ/session extraction keys (`S06Grb`, `oPEP7c`, `FdrFJe`, `cfb2h`, `f.sid`) are centralized as named constants.
- [x] **MAINT-05**: RPC identifier constants are complete and consistently named for every batchexecute RPC (including `otAQ7b` / `Fd0Qje`).

### Model, Chat & Upload Constants

- [x] **MAINT-06**: Model category enum values, display strings, and fallback derivation keywords are centralized and not duplicated.
- [x] **MAINT-07**: Chat message roles (`user`, `model`) are constants; no inline role strings remain in production code.
- [x] **MAINT-08**: MIME type constants for supported images, audio, video, PDF, and upload media validation are centralized.
- [x] **MAINT-09**: Upload endpoint strings (`push.clients6.google.com`, upload command headers, `x-goog-upload-*` header names, tenant id) are centralized.

### Infrastructure Constants

- [x] **MAINT-10**: Base URL constants (`gemini.google.com`, WAA, OGADS, push) are centralized.
- [x] **MAINT-11**: Static header names and values (`x-client-data`, `x-goog-ext-*`, `sec-ch-ua-*`, `User-Agent`, `Origin`, `Referer`, cache pragmas, fetch metadata) are centralized.
- [x] **MAINT-12**: HAR/redaction strings (HAR version, creator name, MIME types, secret header names, cookie names, redaction pattern list) are centralized.
- [x] **MAINT-13**: Transient WIZ 400 markers (`er`, `di`, `af.httprm`) and NotSignedIn diagnostics strings are centralized.
- [x] **MAINT-14**: Tracing / metrics operation names and metric names are centralized as constants.
- [x] **MAINT-15**: Browser attestation CDP method names, selectors, and default strings are centralized.
- [x] **MAINT-16**: Tool schema keys (`type`, `properties`, `required`, `name`, `parameters`) are centralized.

### Test & Example Cleanup

- [x] **MAINT-17**: Magic strings in tests and examples are replaced by constants from the source modules they exercise; shared test constants live in a `tests/common` module if needed.
- [x] **MAINT-18**: A regression gate (clippy lint or dedicated test) prevents new literal occurrences of the eliminated magic strings in `src/`.
- [x] **MAINT-19**: `cargo test --all-targets`, `cargo clippy --all-targets -- -D warnings`, and `cargo doc --no-deps` pass after all v0.3 changes.

## Notes

- Intentional residual inline literals remain in test fixtures, parser fixtures, and fixture response payloads so tests continue to assert against real captured protocol shapes.
- Doc comments may still reference literal protocol values (`/app`, `wrb.fr`, etc.) where they describe the wrapped protocol.
- The regression gate deny-list is conservative and targets only high-risk protocol literals that are cheap to centralize; it does not claim to eliminate every literal occurrence.
