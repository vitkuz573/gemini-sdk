<feature>
  <name>tracing spans across SDK operations</name>
  <files>src/client.rs, tests/unit/tracing.rs</files>
  <behavior>
    - `generate`, `generate_stream`, `list_models`, and `verify_signed_in` each create a span named after the operation (e.g., `gemini.generate`, `gemini.list_models`).
    - Span fields include only non-sensitive metadata: operation name, model category, and byte counts where useful.
    - Upload path has a debug span around `upload_file` with `bytes` field.
    - WAA init chain has an info span around `run_waa_init_chain`.
    - Response parsing has a debug span around `parse_chat_response`.
  </behavior>
  <implementation>
    Add `#[tracing::instrument(level = "info", skip_all, fields(operation = "gemini.generate", category = ?category))]` to public async methods. For `generate_stream` skip the message content. Inside `upload_file` enter `tracing::debug_span!("gemini.upload_file", bytes = bytes.len()).entered()`. Inside `run_waa_init_chain` enter `tracing::info_span!("gemini.waa_init_chain").entered()`. Add `tracing::debug_span!("gemini.parse_response")` around `parse_chat_response` calls in the client. In tests use `tracing_subscriber::fmt` or a custom layer to capture span names.
  </implementation>
</feature>
