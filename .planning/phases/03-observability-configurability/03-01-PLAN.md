<feature>
  <name>HttpHook request/response callbacks</name>
  <files>src/client.rs, src/lib.rs, tests/unit/hooks.rs</files>
  <behavior>
    - A hook set on a client is called once per `generate`, `generate_with_conversation`, and `generate_stream` after the request is prepared and after the response is parsed.
    - `on_request` receives a reference to the prepared request (prompt text and inline image counts, no raw cookies).
    - `on_response` receives a reference to the parsed `ChatResponse`.
    - If the hook returns an error, the SDK logs a `tracing::warn!` and continues by default.
    - A `ClientConfig` flag `fatal_hook_errors` (default `false`) makes hook errors abort the request when set to `true`.
  </behavior>
  <implementation>
    Define a public `HttpHook` trait in `src/client.rs` using the boxed-future pattern from `CredentialsProvider`. Add `http_hook: Option<Arc<dyn HttpHook>>` and `fatal_hook_errors: bool` to `ClientConfig`. Add `GeminiClient::with_http_hook(self, hook: impl HttpHook) -> Self` as an async builder (mirror `with_max_retries`). Add helper `run_hook` that logs errors and respects `fatal_hook_errors`. Call `run_hook` in `generate`, `generate_with_conversation`, and `generate_stream` after parsing. Re-export `HttpHook` from `src/lib.rs`.
  </implementation>
</feature>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Information Disclosure | `HttpHook` callback data | high | mitigate | Hook receives typed `PreparedRequest`/`ChatResponse`, never raw cookies or auth headers; spans use `skip_all`. |
| T-03-02 | Denial of Service | `HttpHook::on_request` panic | medium | mitigate | Hook errors are caught and non-fatal by default; `fatal_hook_errors` is opt-in. |
| T-03-03 | Tampering | User hook mutates shared state | low | accept | Hook trait takes immutable `&self`; document that implementers must not abuse `unsafe` or interior mutability to alter requests. |
</threat_model>
