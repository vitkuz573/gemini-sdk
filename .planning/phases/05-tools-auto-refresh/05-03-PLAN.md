    - If refresh_on_auth_error is false, NotSignedIn propagates unchanged.

Add GeminiClient::with_provider(self, provider: impl CredentialsProvider + 'static) -> Self async builder method that stores the provider in Inner. Add pub async fn refresh_credentials<P: CredentialsProvider>(&self, provider: P) -> Result<()> that awaits provider.credentials(), converts to Cookies, replaces self.inner.cookies, clears session state (reset to SessionState::new with language preserved from config), then calls self.init_session(). In generate_with_conversation (and generate_with_tools), after the first NotSignedIn error, if the stored provider exists and the request was built with refresh_on_auth_error enabled, call refresh_credentials with the stored provider and retry once. Add ChatBuilder::with_refresh_on_auth_error(bool) in src/chat.rs and a refresh_on_auth_error flag in PreparedRequest so the request path knows whether to retry. Add tests in tests/auth_provider.rs for explicit refresh using a mock provider, and in tests/integration_tests.rs for retry-on-auth-error with a wiremock sequence that first returns a signed-in failure and then succeeds.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-05-06 | Denial of Service | Metrics attributes | medium | mitigate | Attributes are low-cardinality strings; never emit user content or raw tool args. |
| T-05-07 | Elevation of Privilege | Provider retry | medium | mitigate | Retry only once on NotSignedIn; do not retry on permanent errors. |
