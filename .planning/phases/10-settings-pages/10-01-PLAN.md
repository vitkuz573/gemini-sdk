<objective>
Implement two thin public APIs on `GeminiClient` for the undocumented settings-page `batchexecute` RPCs (`jSf9Qc` for usage stats, `XPSWpd` for scheduled prompts). Both responses are wrapped in dedicated structs over `serde_json::Value` to satisfy SETTINGS-03 and preserve forward compatibility against protocol drift. The work follows the existing `src/locale_model_config.rs` module pattern and uses configurable `base_url` + Wiremock fixtures for tests.

Purpose: Complete the settings-page surface of the v0.2 API expansion milestone while keeping responses opaque enough to tolerate undocumented shape drift.
Output: New `src/settings.rs` module, two client methods, re-exports, two fixtures, and integration tests.
</objective>

  <action>
    Create `src/settings.rs` mirroring `src/locale_model_config.rs` patterns.

    Define two public wrapper structs, each with a single private `value: serde_json::Value` field and a `pub fn value(&self) -> &serde_json::Value` accessor:
    - `UsageStats`
    - `ScheduledPrompts`

    - `pub fn build_get_usage_stats_payload() -> Value` → `[]`
    - `pub fn build_get_scheduled_prompts_payload() -> Value` → `[]`

    Implement response parsers:
    - `pub fn parse_usage_stats_response(body: &str) -> Result<UsageStats>`
    - `pub fn parse_scheduled_prompts_response(body: &str) -> Result<ScheduledPrompts>`

    Each parser must:
    1. Strip the XSSI prefix using `crate::proto::strip_xssi_prefix`.
    2. Parse the outer batchexecute envelope and locate the RPC entry matching its RPC ID (reuse the `find_rpc_entry` / `extract_payload_str` logic from `locale_model_config.rs`, copying the helpers if necessary).
    3. Parse the inner payload string into `serde_json::Value`.
    4. Return the wrapper struct containing that value.

    Include `#[cfg(test)] mod tests` with:
    - One payload-shape test per builder asserting equality against `serde_json::json!([])`.
    - One parser test per parser using a synthetic batchexecute body with XSSI prefix and asserting the extracted `Value` matches the expected payload.
    - One test for the wrapped-array envelope shape per parser (copy the wrapped-array pattern from `locale_model_config.rs` tests).

    Do NOT create brittle typed structs for the inner payloads. Do NOT add new dependencies.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → Gemini frontend | Untrusted network; cookies and RPC payloads cross this boundary. |
| SDK public API → internal parser | Callers receive opaque `serde_json::Value` wrappers; no PII is strongly typed. |
| Test → mock server | Integration tests use synthetic fixtures; no live secrets. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-01 | Information Disclosure | `get_usage_stats` / `get_scheduled_prompts` | low | accept | Responses are opaque JSON values; no PII is parsed or logged at info level. Existing cookie redaction in `Cookies::Debug` covers auth headers. |
| T-10-02 | Tampering | Request payloads in transit | medium | mitigate | Reuse existing HTTPS transport and retry logic; no plaintext fallback. Configurable `base_url` still defaults to `https://gemini.google.com`. |
| T-10-03 | Denial of Service | Parser on malformed batchexecute envelope | low | mitigate | Parser returns structured `Error::Parse` instead of panicking; unit tests cover missing RPC entries and wrapped arrays. |
| T-10-04 | Elevation of Privilege | Test helper `inner_session_for_tests()` | low | accept | Already public and documented as test-only; no new capabilities added by this phase. |
| T-10-SC | Tampering | No new packages installed | — | mitigate | No package-manager install tasks; existing `wiremock` dependency is reused. |
</threat_model>
