<objective>
Eliminate blocking-lock panics and silent attestation failures, and fix cookie merge persistence.

Purpose: These are the highest-risk reliability bugs in the current SDK — they can crash callers or silently degrade behavior. Fixing them first isolates public-API breaking changes and makes later protocol work safer.
Output: Async client config builders, typed attestation errors, and consent cookies that survive the consent handshake.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller -> GeminiClient config | Async methods now cross the async runtime boundary safely. |
| WAA/ogads service -> SDK | Failure is surfaced instead of hidden; no silent downgrade to default context. |
| consent.google.com -> client cookie jar | Merged cookies must not be dropped before the next request. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Denial of Service | `with_language` / `with_max_retries` / `with_timeout` | high | mitigate | Replace `StdMutex::blocking_lock` with `tokio::sync::RwLock` and async methods. |
| T-02-02 | Information Disclosure | `Error::AttestationFailed` messages | medium | mitigate | Construct reason strings from transport/parse errors without including cookie values or request headers. |
| T-02-03 | Tampering | consent cookie merge | medium | mitigate | Merge inside a single lock scope and verify persisted jar is used for the refetch. |
| T-02-SC | Tampering | cargo installs | low | accept | No new external dependencies in this plan. |
</threat_model>
